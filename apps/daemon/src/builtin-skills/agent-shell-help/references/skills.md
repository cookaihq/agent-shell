# 技能库管理

本文说明如何在「集成 › 技能」管理技能分组与来源、把技能加入技能库、设置默认注入、以及更新来源。

---

## 核心概念（分组 / 成员 / 库 / 注入）

- **分组（group）**：顶层容器，给「一组来源」起个名字。**一个分组可以装多个来源（成员）**——既能放本地文件夹，也能放 Git 仓库。列表里一行 = 一个分组。
- **成员（member）= 来源（source）**：分组里的一个真实来源（本地文件夹 / Git 仓库），各自带自己的地址、分支、私有凭据、更新策略，独立探测出技能。
- **技能库（library）**：从各成员中**手动挑选**加入的技能合集（探测到的技能不会自动入库，除非该成员用「自动更新+入库」托管整源）。
- **注入（inject）**：某次具体任务真正用到的技能，从技能库里选定。

一句话：**分组** 是「这组叫什么」，**成员** 是「组里有哪些来源」，**库** 是「我留下了哪些技能」，**注入** 是「这次用哪些」。系统单例分组「内置」「自建」不可编辑、不可往里加成员。

---

## 技能管理在哪里

在左侧导航栏（rail）点击「集成」，进入集成页后选「技能」tab。该页左右分栏：

- **左列**：置顶一个「技能库」总览条目，下方是「技能分组」列表（可拖拽重排），以及「添加分组」按钮。每个分组行显示「N 来源 · M 技能 · 已加入 K」，任一成员为私有库则打「私有」标。
- **右列**：选中左列某项后显示其详情——选中「技能库」显示库里的技能合集；选中某个分组显示该分组详情（见下）。

### 分组详情（右列）

选中一个分组后，右列分三段：

1. **头部**：分组名（可重命名）、`更新全部`、`添加成员 ▾`（落点是当前分组）、`删除分组`（删分组会连带移除其成员；系统单例分组「内置」「自建」不可改名/删除/加成员）。
2. **紧凑成员条**：每个成员一行，自带「更新策略下拉 / 重新探测 / 编辑 / 移除」。空分组显示加成员引导文案。
3. **聚合技能**：该分组下**所有成员**探测出的技能合集，每行标出来自哪个成员；带「已入库 / 未入库 / 全部」筛选 + 搜索 + 批量「全选加入 / 全部移出」（作用于整组）+ 入库行的「默认注入」开关 + 点开看 SKILL.md。

---

## 添加技能：先建分组，再往分组里加成员

先点「添加分组」新建一个空分组（自动选中并进入重命名）。进入分组详情后，点「添加成员 ▾」展开菜单，可选两种来源类型加入**当前分组**：

### 本地文件夹

在弹窗中填入文件夹的绝对路径（或点「选择…」通过系统文件夹选取器选择），填写可选的来源名称（留空则自动取文件夹名），点「探测并添加」。添加后系统会扫描该文件夹内的 SKILL.md，探测出的每个含 SKILL.md 的目录算作一个技能。

### Git 仓库

在弹窗中选择托管平台（GitHub / 码云 Gitee / CNB / GitLab / 其它自建），填入仓库地址，可选填分支（留空默认 main）。

**私有库认证**：打开「私有库」开关后，按所选平台展示对应的认证字段：

- **GitHub / GitLab**：填 Personal Access Token（可选用户名）
- **CNB / 码云 Gitee / 其它自建**：填 Git 用户名 + Token

凭据仅保存在本机系统钥匙串，仅用于克隆/更新该仓库。

点「探测并添加」后系统会克隆仓库并扫描其中的 SKILL.md。

### 技能市场（暂未开放）

菜单中有「技能市场」选项，目前标注「即将上线」，点击无实际效果。

---

## 探测规则

添加来源后，系统按以下规则扫描：

- 源的根目录如果**有 SKILL.md**，则整个目录算作 1 个技能，不再向下递归。
- 根目录**没有 SKILL.md**，则逐级向下递归，把每个含 SKILL.md 的目录各算一个技能；每条路径遇到第一个 SKILL.md 即停（已是技能的目录内部不再继续找）。

---

## 把技能加入技能库（入库）

在左列点击某个来源，右列会显示该来源探测到的所有技能。点击某个技能行，弹出 SKILL.md 预览弹窗，底部有「加入技能库」开关。打开开关即把该技能加入库；关闭则移出库。

也可以在来源详情页通过「全选加入」/「全部移出」批量操作。

技能库视图（选中左列「技能库」）提供筛选和搜索：

- **筛选**：已入库 / 未入库 / 全部 / 自动注入 N（筛出已打开默认注入开关的技能）
- **搜索**：按技能名、描述或路径关键词搜索

---

## 默认注入（autoInject）

在「技能库」视图的已入库技能列表中，每行右侧有一个「默认注入」开关。打开该开关意味着：**新建项目时这个技能会自动预选进注入集**，无需每次手动勾选。

具体行为：

- 在首页（composer 大输入框）发任务建项目时，「注入技能」弹窗的初始选中项 = 所有已打开「默认注入」的技能。用户可在弹窗里增加或取消。
- 通过右上角「添加项目」按钮（无技能选择 UI）新建项目时，系统静默注入默认注入集，无需用户操作。

**注意**：默认注入只影响新建项目，不会回溯已有项目。

**内置技能在注入弹窗里的呈现**：AgentShell 自带的内置技能（如 install-skill）默认始终注入，在「注入技能」弹窗中带「内置」标签、排在列表末尾，且**不计入**「注入技能」入口的数字徽标与弹窗底部的「已选 N 个」——那两个数字只统计你自己额外勾选的非内置技能。

## 更新来源（成员）

在分组详情的**紧凑成员条**上，每个成员一行自带操作：

- **重新探测**：重新扫描成员目录（本地文件夹）或重新 pull 并扫描（Git 仓库），刷新探测到的技能列表。
- **编辑**：修改成员的路径、分支、私有库认证等配置。
- **移除**：从分组里移除该成员（内置来源不可删除）。

分组头部的 `更新全部` 会重新探测该分组下所有成员。每个 Git 成员还可在成员条上设置**更新策略**（三档）：

| 档位 | 说明 |
|------|------|
| **手动** | 上游有新版本只提示，需手动「重新探测」才拉取；是否入库由用户决定。 |
| **自动更新** | 源有新版本时自动拉取并重新探测；新技能不会自动入库，由用户挑选。 |
| **自动更新+入库** | 源有新版本时自动拉取并重新探测，新技能自动加入技能库（整源托管）。 |

---

## 首次启动的默认预置（可删除）

首次启动 Agent Shell 会自动预置两类内容，**都可被用户删除**（删了不会重新出现）：

- **「推荐技能」分组**：一个普通用户分组，内含多个 Git 成员，更新策略均为「自动更新+入库」：
  - `cookaihq/awesome-skills`：其技能默认打开「默认注入」（新建项目即自动带上，开箱即用）。其中 `banana-2` / `image-2` 这两个需要密钥的技能，已**出厂预绑到 FoxAPI 密钥占位**——用户只需去「设置 · 密钥管理」给 FoxAPI 占位填值，填完即可用。
  - `heygen-com/hyperframes`（HTML→视频渲染框架，含多个细分技能）、`cookaihq/ppt-skill`（生成 HTML 幻灯片）、`cookaihq/social-card-skill`（生成小红书/公众号图文卡片）：整源自动入库，但**默认不注入**（不常驻每个新会话的上下文），由 agent 按场景需要时调用；也不预绑密钥。
- **常用密钥占位**：三个「有名无值」的占位 `FoxAPI Key` / `DeepSeek Key` / `MiniMax Key`，备注里带「去哪申请」的获取链接（可点）。占位为空值时，引用它的技能显示「需配置」；填值后转「已配置」。

---

## 密钥与配置

需要密钥的技能可在其 SKILL.md 预览弹窗右侧的配置面板中绑定密钥，也可点击右上角「管理密钥」快捷入口。**绑定了密钥但该密钥是空值占位时，仍算「需配置」**（运行时不会注入空值），需先去设置给密钥填值。密钥细节见「密钥管理」参考文档（secrets.md）。

---

## 全局技能同名预警

如果用户全局引擎目录（`~/.claude/skills/` 或 `~/.codex/skills/`）里已有与库内技能同名的技能，技能行会显示预警标识（如「⚠ Claude 全局」），说明注入到项目级的同名技能会被全局技能覆盖、实际不生效。遇到此提示时，需在对应引擎的全局技能目录检查并处理同名冲突。
