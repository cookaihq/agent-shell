# 给技能配密钥与配置项

本文说明如何给技能绑定密钥、如何管理命名密钥，以及密钥注入的工作方式。  
技能库的添加与管理（添加来源、入库、默认注入）见 skills.md，本文只讲密钥/配置本身。

---

## 核心概念

- **命名密钥**：有名字的密钥条目（如"高德 Key"），集中存储在密钥管理子页，可被多个技能共用。
- **配置面（ConfigPanel）**：技能详情弹窗右侧的配置区，列出该技能需要的密钥/配置项，供用户逐项绑定。
- **绑定**：把某个配置槽位（如"环境变量 GAODE_API_KEY"）指定为哪个命名密钥；运行时 AgentShell 按绑定关系把密钥值注入引擎子进程，不落盘。
- **槽位（slot）**：一个技能的一条配置需求，类型为「环境变量」或「配置文件」，可以是必填或选填。

---

## 给技能配密钥（配置面操作）

### 打开配置面

在「集成 › 技能」里，点击任意一个已探测到的技能行，会弹出技能详情弹窗（SKILL.md 预览），右侧即为「配置」区。

### 配置面的三种状态

1. **未探测**：显示提示「尚未探测，点「重新探测」让 Agent 读 SKILL.md 与脚本，列出需要的密钥/配置」。此时需先点「重新探测」让系统分析该技能需要哪些配置项。
2. **无需配置**：显示「✓ 无需配置——此技能不读取任何密钥或外部配置」。
3. **有槽位**：顶部显示「探测到 N 项配置，M 项待绑定」或「✓ N 项已全部配置」；下方列出每个配置槽位。

### 重新探测

配置面顶部的「重新探测」按钮（探测中显示「探测中…」）：触发 Agent 读 SKILL.md 及相关脚本，分析需要哪些密钥或配置文件，将结果写入配置列表。探测完成后配置列表刷新。

### 给槽位绑定密钥

每个槽位对应一行，显示类型（环境变量 / 配置文件）和名称，以及绑定状态（已绑定 / 未绑定）。每行有一个下拉选择框：

- **选择已有命名密钥**：从密钥管理子页已建好的命名密钥中挑一个绑上，多个技能可共用同一个密钥。
- **+ 新建密钥…**：选择后在行内弹出表单，填写密钥名称和密钥值，点「创建并绑定」——一步完成在密钥库里新建命名密钥并绑定到当前槽位。

**默认值预填**：若探测时技能声明了默认值，「新建密钥」表单中的密钥值字段会预先填入，用户可直接采用或修改。

绑定操作即时保存，无需额外确认。未绑定的必填槽位会显示「未绑定」警告；绑定后变为「✓ 已绑定」。

### 配置与入库相互独立

配置面随时可操作：**即使技能还未入库，也可以先配置绑定**；绑定数据持久保存。技能入库后绑定自动生效，无需重复配置。

## 注入技能选择器里的配置标志

在新建项目时弹出的「注入技能」选择器（或在配置面之外查看技能库列表时），技能名旁边会显示配置状态标志：

- **「需配置」（橙色）**：该技能需要密钥或配置、但尚有必填槽位未绑定。
- 无标志：无需配置或已全部绑定。

选了带「需配置」标志的技能后，行内会出现「去配置」链接，点击直接跳到「设置 › 密钥管理」，方便当场补填。此外，发任务时若有注入的技能仍有必填槽位未绑定，系统会在启动前弹出预检弹窗，提示三个选项：去配置、仍然运行（该技能可能失败）、本次不注入它。

## 密钥管理子页

### 入口

**密钥管理是「设置」的第 3 个子页（执行模式 / 系统设置 / 密钥管理 / 代理）**。打开方式：

- 点击界面右上角的「设置」图标，弹出设置弹窗，左侧导航选「密钥管理」。
- 技能配置面的「去配置」快捷链接会直接打开设置并定位到密钥管理子页。

> 集成技能页**没有**独立的密钥管理入口（设计文档曾提到该入口，但 SkillModal 和 SkillsSettings 的实际代码中，「去配置」链接跳转目标是 `openSettings('secrets')`，即设置弹窗的密钥管理子页，集成页本身不包含密钥管理 UI）。

### 功能

密钥管理子页集中管理所有命名密钥：

- **新建密钥**：填写名称（必填）、密钥值（必填）、备注（选填），点「创建」保存。
- **编辑密钥**：可修改名称和备注；密钥值留空则不修改原值，填入新值则替换。
- **删除密钥**：点「删除」移除，删除后引用该密钥的绑定也随之失效。
- **脱敏显示**：列表中密钥值以脱敏形式（maskedValue）展示，点击 👁 图标可切换显示/隐藏。
- **用量（谁在用）**：每个密钥行下方显示被哪些**技能**和**上游 Provider** 引用（如「被 2 个引用：高德地图·天气查询、我的中转站」——技能与 Provider 合并计数展示），方便在删除前确认影响范围。一个密钥可同时被多个技能 + 多个 Provider / 官网 API Key 共用。

## 密钥存储与注入机制（供理解，非操作步骤）

- **存储**：密钥明文存储在 `~/.agent-shell/secrets.json`（权限 0600，仅当前用户可读），对齐 providers.json 的存储模式。清单文件只存槽位定义和 secretId 引用，不存明文。
- **注入**：运行任务时，AgentShell 按「本次注入了哪些技能」现场拼装，将环境变量类密钥通过内部 `sanitizeEnv` 机制注入引擎子进程 env；子进程退出后 env 即消失，不落盘、不写入项目目录。
- **自动任务侧密钥**：本版本（V1）**仅技能侧配置已实现**；自动任务的密钥声明/绑定/注入为设计阶段，尚未开放，不可使用。
